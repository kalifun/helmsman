# 文件去重 CLI —— 设计说明

> 目标：用 **Node 零依赖**实现一个**保序去重**的命令行工具。
> 输入一组文件路径，输出其中内容（或路径）重复项被剔除后的列表，且**保留原有顺序**。

---

## 1. 目标与边界

### 1.1 目标

- 对输入的文件路径列表做去重，输出仍保持输入顺序（**首次出现者保留**，后续重复者剔除）。
- 默认按**文件内容**去重（内容一致即视为重复）；提供按**路径**去重的模式。
- 只使用 Node.js 内置模块（`fs` / `crypto` / `stream` / `readline` / `path` / `process`），
  不引入任何 npm 依赖，单个文件即可运行。
- 支持大文件与大量文件：哈希采用流式读取，内存占用有界。

### 1.2 非目标（本期不做）

- 不做跨设备/分布式去重；不做去重后的**物理删除**之外的整理（移动、改名、硬链接合并）。
- 不做增量索引/缓存（每次运行全量计算，见 §6 扩展方向）。
- 不做内容相似度去重（仅精确去重）。

---

## 2. 使用场景与 CLI 形态

```bash
# 从命令行参数输入（最常用）
dedup a.txt b.txt a.txt c.txt            # 输出 a.txt b.txt c.txt

# 配合 find / xargs 管道输入
find . -name '*.log' | dedup

# 文件名可能含换行时用 NUL 分隔（兼容 find -print0）
find . -type f -print0 | dedup --null

# 扫描目录后去重
dedup --recursive --dir ./assets

# 列出重复但不做任何修改（安全演练）
dedup --dir ./photos --dry-run --list-dups

# 删除重复文件（仅保留每组中的首个）
dedup --dir ./downloads --delete --dry-run
```

三种输入方式互斥（`--args` 为默认；指定 `--stdin` 或 `--dir` 后忽略位置参数）。

---

## 3. 语义定义

### 3.1 保序规则

- 输入序列按出现顺序编号。**首个出现的项保留在它原来的位置**，后续与之重复的项从输出中删除，其余项位置不变。
- 例：`[A, B, A, C, B]` → `[A, B, C]`。这是"保序去重"的标准语义（类似 Unix `awk '!seen[$0]++'`）。

### 3.2 去重键（duplicate key）

| 模式 | 键 | 说明 |
|---|---|---|
| `--by-content`（默认） | 文件内容 | 内容字节完全一致即重复 |
| `--by-path` | 规范化路径 | 同一路径（或硬链接同 inode，见下）出现多次即重复 |

### 3.3 分组语义

- 互为重复的一组文件，保留组内**输入顺序最早**的那个（`--keep-last` 可改为保留最晚）。
- 被剔除的项在输出中消失；`--delete` 模式下被剔除者会被删除（须配合 `--dry-run` 演练）。

## 4. 算法设计

### 4.1 整体流程

```
解析参数 → 收集输入路径（args / stdin / 目录扫描） → 逐项判定重复 → 保序输出
```

### 4.2 内容判定：两级过滤

1. **文件大小（O(1)，无 I/O 成本之外的哈希成本）**
   - 大小不同 ⇒ 内容必不同，直接判为不重复。
   - 大小相同的候选才进入哈希比较。用 `fs.stat` 拿到大小（同时拿到 inode，见 4.4）。
2. **SHA-256 流式哈希**
   - `crypto.createHash('sha256')` + `fs.createReadStream` 逐块（默认 64 KB）喂入，
     `hash.digest('hex')` 得 64 字符键。流式处理 ⇒ 内存占用与文件大小无关。
   - 哈希缓存：同一次运行内，同一路径第二次出现直接复用哈希结果（按路径去重 + 内容判定同时生效）。

### 4.3 去重表与保序输出

- `seen: Map<key, firstIndex>`：键 → 首次出现的输入序号。
- 输出阶段按输入顺序遍历：`seen` 中该键的 firstIndex 等于自身序号 ⇒ 输出；否则 ⇒ 剔除。
- 复杂度：时间 `O(n)`（每次判定均摊 O(1)，哈希为瓶颈 I/O）；空间 `O(去重后条数)`（seen 表 + 输出缓冲）。

### 4.4 硬链接快速通道（可选优化）

- `fs.stat` 返回 `dev + ino`。同一文件系统内硬链接指向同一 inode，内容必然一致。
- `--hardlink-dedup`（默认开启）下，先按 `dev:ino` 判重，命中者**跳过哈希**，直接复用同组首个的键。
- 注意：`dev:ino` 只在本机有意义，不能跨机器/跨设备混用（设计上不跨设备去重，无此问题）。

### 4.5 空文件边界

- 所有空文件内容一致 ⇒ 互为重复。行为与定义一致（保留首个），但要在文档与 `--verbose` 输出中明示，避免用户困惑。

## 5. CLI 接口设计

### 5.1 参数表

| 参数 | 说明 | 默认 |
|---|---|---|
| `paths...` | 位置参数，直接作为输入路径 | — |
| `--stdin` | 从 stdin 读取路径（每行一个） | 无 stdin 时自动启用 |
| `--null` / `-0` | 输入/输出用 NUL 分隔（配合 `find -print0` / `xargs -0`） | 关闭 |
| `--dir <d>` | 扫描目录；配合 `--recursive` 递归 | 无 |
| `--recursive` | 递归扫描 `--dir` | 关闭 |
| `--by-content` | 按内容去重（默认） | 开 |
| `--by-path` | 按规范化路径去重 | 关 |
| `--keep-first` / `--keep-last` | 重复组保留首个 / 最末 | `--keep-first` |
| `--delete` | 删除被剔除的文件（危险操作） | 关 |
| `--dry-run` | 只报告将做什么，不实际删除 | `--delete` 开启时强制为演练要求 |
| `--list-dups` | 额外输出重复组明细（组内各成员） | 关 |
| `--verbose` | 向 stderr 输出进度（哈希/判定过程） | 关 |
| `--skip-errors` | 读失败/stat 失败的文件跳过而非报错退出 | 关 |
| `--no-hardlink-dedup` | 关闭硬链接快速通道 | 硬链接通道开 |
| `--help` / `-h`、`--version` / `-v` | 帮助 / 版本 | — |

### 5.2 输出契约

- **stdout**：只输出结果列表（每行一个路径，顺序保序），保证可继续管道给下游（`xargs` / 循环）。
- **stderr**：日志、警告、错误（`--verbose` 的进度、`--dry-run` 的演练清单）。
- 程序性输出与日志严格分离，是"CLI 可组合性"的第一原则。

### 5.3 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功（含 `--dry-run` 演练完成） |
| 1 | 运行期错误（参数非法 / 文件不可读且未 `--skip-errors`） |
| 2 | 用法错误（未知参数、互斥参数冲突、缺必需参数） |

### 5.4 路径规范化

- 输入路径统一 `path.resolve` 后比较（避免 `./a` 与 `a` 判为不同）。
- 相对路径**输出时保持用户原始写法**（仅判定时用规范化形式），尊重用户观感与管道语义。
- 符号链接默认**不跟随**（`lstat`，目录扫描时按链接本身记录）；`--follow-symlinks` 开启跟随。

## 6. 零依赖实现要点

1. **单文件结构**：`dedup.js`（或 `bin/dedup`，shebang `#!/usr/bin/env node`），
   内部按函数拆分，便于单测直接 `require`/`import`：

   ```
   parseArgs(argv) → Config
   collectInput(cfg) → string[]        // args / stdin / 目录扫描
   keyOf(path, cfg) → Promise<string>  // size+hash 两级判定（含 dev:ino 快通道）
   dedupe(list, cfg) → {kept[], groups[], removed[]}
   render(result, cfg) → void          // stdout 输出 + stderr 报告
   main(argv) → exitCode
   ```

2. **只用的内置模块**：`fs`（stat/createReadStream/readdir）、`crypto`（sha256）、
   `stream/promises`（pipeline，流式哈希）、`readline`（stdin 逐行）、`path`、`process`、`util`（promisify 或直接 `fs.promises`）。
3. **内存有界**：哈希全程流式；输出结果即使全量驻留，量级为"路径字符串 × 去重后条数"，可接受。
4. **并行哈希（可选）**：大量文件时以固定并发（如 4）并行做 size/stat 与哈希（I/O 密集），
   结果按输入序号归位，不破坏保序输出。实现只用内置 `Promise`，无需并发库。
5. **错误隔离**：单个文件 stat/读取失败默认终止（退出码 1）并指出文件；`--skip-errors` 时跳过并计数汇总到 stderr。

---

## 7. 边界情况与错误处理清单

| 场景 | 行为 |
|---|---|
| 空输入（无参数、stdin 空、目录为空） | 输出空，退出码 0 |
| 空文件 | 全部互为重复，保留首个 |
| 文件在运行中被修改/删除 | stat 或读流失败 ⇒ 按错误处理（见 6.5） |
| 路径不存在 | 默认报错退出 1；`--skip-errors` 跳过 |
| 文件名含换行符 | 非 `--null` 模式下警告（输入会被错误切分），建议 `-0` |
| 路径含空格/中文/Unicode | 逐行/NUL 传输天然安全；内部一律 UTF-8 |
| 目录扫描遇权限不足的子目录 | 默认报错；`--skip-errors` 跳过该子树并汇总 |
| 同名文件经不同路径引用（`a` 与 `./a`） | 规范化后视为同一路径 ⇒ 按路径模式判重 |
| `--delete` 无 `--dry-run` | 允许执行，但 `--verbose` 下逐条打印删除操作；文档强烈建议先演练 |
| 硬链接同一 inode 但路径不同 | 内容必相同，走快通道判重（默认开启） |

## 8. 测试与验收标准（给后续实现）

> 本任务只交付设计说明；以下为实现时的验收基线，供开发与评审引用。

1. **保序正确性**：`[A,B,A,C,B]` 内容去重输出 `[A,B,C]`；`--keep-last` 输出 `[A,C,B]`。
2. **内容 vs 路径模式**：两个不同路径的同内容文件：`--by-content` 视为重复、`--by-path` 视为不重复。
3. **大小快通道**：不同大小文件不触发哈希（可用 `--verbose` 观察或注入计数验证）。
4. **硬链接快通道**：对同一 inode 的两个路径，不重复哈希。
5. **大文件**：≥ 1 GB 文件在内存峰值 < 100 MB 的约束下完成去重（流式哈希验证）。
6. **管道兼容**：`find ... -print0 | dedup -0 | xargs -0 ...` 全链路可用。
7. **退出码**：用法错误 → 2；文件不可读且未 `--skip-errors` → 1；其余 → 0。
8. **`--dry-run` 不落盘**：演练模式下文件系统零修改（可用临时目录前后 `stat` 对比验证）。
9. **零依赖校验**：`npm ls`（或 `node_modules` 不存在）且仅内置模块被 `require`。

## 9. 参考语义（业界对照）

- Unix 惯例：`awk '!seen[$0]++'` —— 保序去重的经典实现，本工具是它的"文件内容版"。
- `fdupes` / `rdfind` / `jdupes`：内容去重但**不保序输出**（按组/按大小排序），且依赖 C 生态；
  本工具定位是其"零依赖、保序、可管道"的 Node 替代。
- `fdupes -N` 的"保留首个"与 `--delete` 语义与本设计一致，可作为行为对拍基准。
